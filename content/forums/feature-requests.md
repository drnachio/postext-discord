Suggest improvements to Postext and vote on others' ideas with 👍.

Search before posting: if your idea already exists, upvote it and add your use case instead of opening a duplicate. One idea per post. Describe the problem before the solution: what are you trying to publish, and what gets in the way?

Status tags (Under review, Planned, In progress, Shipped, Not planned) are set by maintainers. Accepted ideas are tracked on GitHub.
<!-- pinned post: 📌 How to write a great feature request -->
**Great requests start with the problem, not the solution.** Use this template:
```
**The problem:** What are you trying to do? What gets in the way today?
**Who it affects:** Publishers, developers, readers...?
**Proposed solution:** (optional) How you imagine it working
**Alternatives / workarounds:** What you do today instead
**Examples:** Print references, screenshots, other tools that do it well
```
📚 Print references are gold. A photo of how a book or magazine handles something tells us more than a thousand words.

**What happens next:** maintainers review requests and set a status tag. 🔍 *Under review* → 🗺️ *Planned* → 🚧 *In progress* → 🚀 *Shipped*. Planned work is tracked in [GitHub Issues](<{link:github}/issues>), and that's where implementation discussion continues.

Upvote with 👍 the ideas you'd use. It really helps us prioritise.
